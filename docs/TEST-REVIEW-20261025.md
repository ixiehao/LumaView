## 已确认问题

### P2 · 语言变更后底部错误状态仍使用旧语言

**影响：** 同一个窗口混用两种语言；不导致图像损坏，也不阻断继续浏览。

**复现：**

1. 应用语言选择 English，打开损坏但扩展名受支持的 JPG。
2. 等待中央和底部出现 `Unable to preview this image.`。
3. 打开 Settings，语言改为 Français，然后关闭 Settings。
4. 中央错误和工具栏已变为法语；底部 `image.status` 仍显示英文 `Unable to preview this image.`。

**实际 AX 证据：**

- `canvas.unavailable.05-broken.jpg`：`Impossible d’afficher un aperçu de cette image. 05-broken.jpg`。
- `image.status`：`05-broken.jpg, 5 / 5, Unable to preview this image.`。

**定位：** `LumaView/ImageCanvasView.swift:358` 将当前语言下已经翻译的错误字符串传给存储；`LumaView/ImageBrowserStore.swift:303`、`:363–364` 保存字符串；`:354` 直接返回该旧值。语言切换没有重算这条状态。

**建议：** 存储语义化错误/状态，显示时使用当前 `L10n` 格式化；至少为切换语言后的现存错误状态补回归断言。`statusMessage` 的空目录、打印准备/失败等分支也有同类字符串快照，但本轮未逐项复现，不能作为额外已确认缺陷计数。

### P3 · QA 清单仍按三语言编写

`docs/QA.md:8` 仍只要求 English、简体中文、日文的浅/深色检查，遗漏法语、俄语、西班牙语和韩语。生产代码已经七语言；未来执行该清单容易漏测新语言。

`docs/QA.md:41–42` 关于全屏测试使用原生控件的说明，与当前 SwiftUI 管理全屏命令及快捷键回归策略应一并核对更新。该条属于文档一致性，不是本轮已复现的功能故障。

## 代码风险与环境限制

- **Swift 6 迁移风险，非已复现运行时缺陷：** 当前 CI 以 Swift 5 模式成功构建，但有并发捕获/Sendable 警告，涉及 `LumaView/LumaViewApp.swift:1208–1214`、`LumaView/ImageBrowserStore.swift:644`、`:865–869`。升级严格并发模式前需要逐项处理，不宜仅关闭警告。
- **后台占位语义风险：** `ImageCanvasView.swift:68–70` 在画布暂停时释放图像，`:148–149` 将仍有选中文件的空画布显示为预览失败。CUA 焦点/遮挡变化期间观察到该占位；前台恢复后图像正常。因此不记录为“图片打不开”。若窗口缩略预览或辅助功能需要区分暂停与失败，可为暂停保留独立语义。
- **工具截图边界：** 原生 popover 可以超出主窗口；只截主窗口会裁掉超出部分。全屏转场时截图与 AX 可能来自不同瞬间，不能用单张转场截图推导最终窗口尺寸。测试过程中出现 CUA 的用户切换应用提示时均重新读取状态，没有把焦点冲突当成应用缺陷。
