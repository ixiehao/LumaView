## 缓存与异步复核

选择序号只控制画布任务身份，不参与共享解码缓存的键。缓存仍由文件指纹与解码尺寸组成；新增回归验证不同窗口的请求能够复用同一个已解码对象，避免按选择次数产生额外缓存。

异步结果写回同时检查操作身份、当前请求、选择序号与 URL。窗口调整大小和缩放仍可沿用同一次选择的当前画面；旋转继续复用图片并更新几何。没有新增主线程文件属性读取、持久化缓存或后台服务。

代码复核还确认：同路径重开时，乐观的热预览可能仍来自替换前的文件指纹。已追加最小修正，跳过该次选择的热预览，等待校验文件指纹后的解码结果；这一决定也会保留到元数据改变窗口尺寸之后。追加修正后的完整核心测试再次 52 项通过，Release Universal 与 build-for-testing 构建成功。

## 可复用的工程经验

1. 文档格式的“逻辑尺寸”和位图“像素尺寸”并不相同。PDF 等矢量表示可能合法返回 0 个像素，窗口布局需要明确回退策略。
2. URL 不是一次打开操作的完整身份。同路径文件可以被编辑或替换；任务身份使用选择序号，内容缓存使用文件指纹，窗口比例使用实际尺寸，各自独立。
3. 格式化相机元数据时不能为了常见展示形式改写其数值。快门分数需要验证误差，极值需要避免整数转换溢出。
4. 持久化限流记录应处理时钟回拨。负时间差不属于正常限流区间。
5. 先让可复现用例失败，再修复并执行相关完整套件；窗口尺寸和画面效果仍应以真实 UI 回归确认。
